> 文档版本：v1.0（设计阶段）

## 1. 设计目标

- 一个页面完成"添加学生 → 开始点名 → 签到 → 结束点名 → 查看记录"主流程。
- 教师视角与学生视角共用页面：教师操作区在顶部，学生签到区在点名进行时突出显示。
- 简洁美观：浅色背景、单一主色、卡片式布局、清晰层级、适度动效，不堆叠装饰。
- 移动端优先适配：360px 起可用，签到按钮足够大。

### 3.3 各区域功能

#### ① 添加学生卡片

- 字段：`name`（必填，1–32 字符）、`student_no`（必填，1–32 字符）、`role`（下拉：学生/班长/教师，默认"学生"）。
- 点击"添加学生"：
  1. 前端校验非空、长度、学号格式（字母数字，允许 `-`）。
  2. 调用 `POST /api/v1/students`。
  3. 成功：清空姓名与学号（保留角色）、刷新名单、`ElMessage.success("添加成功")`。
  4. `40901`：学号输入框下方提示"该学号已存在"。
  5. 其他错误：`ElMessage.error(message)`。
- 提交中禁用按钮，防止重复提交。
- 支持回车提交。

#### ② 点名控制卡片

- 未开始：显示"开始点名"按钮，禁用条件为名单为空（也可点击后由后端返回 `40905`，前端双保险）。
- 点击"开始点名"：
  1. 调用 `POST /api/v1/rollcalls`，body 可传 `{ "order_by": "student_no" }`。
  2. 成功后将返回的 `SessionDetail` 写入 Store，按钮变为"点名结束"。
  3. 启动顺序轮播：按 `records` 的 `order_no` 升序，每 3 秒高亮下一位（到末尾后停在最后一位或循环，产品选择：循环轮播）。
  4. 当前学生卡片展示姓名、学号、"签到"按钮。
- 点击"点名结束"：
  1. 弹出确认框"结束后未签到学生将记为缺勤，确认结束？"。
  2. 调用 `POST /api/v1/rollcalls/{id}/end`。
  3. 成功：停止轮播，按钮置灰为"已结束"，刷新签到/缺勤记录与统计，`ElMessage.success("点名已结束")`。
  4. 若返回 `40903`：提示并同步场次状态。
- 页面刷新恢复：将 `session_id` 存入 `sessionStorage`；刷新后调用 `GET /rollcalls/{id}`，若 `status=calling` 则恢复轮播与按钮状态；若 `40402` 则清除本地缓存。

#### ③ 学生名单

- 数据来源：`GET /api/v1/students`（默认 `active=true`）。
- 展示：姓名、学号、角色、本次状态（未点名时显示"—"；点名中按 `records` 映射为"已签到/待签到/缺勤"）、操作（删除）。
- 删除：二次确认后调用 `DELETE /students/{id}`（软删除），成功后刷新名单。点名进行中删除学生仅影响下一次场次，不改变当前场次记录。
- 名单为空时显示空状态："还没有学生，请先添加"。

#### ④ 签到记录

- 来源：当前 `SessionDetail.records.filter(r => r.status === "present")`。
- 列：姓名、角色、学号、签到时间（本地时区格式化）。
- 默认按 `checked_at` 升序或 `order_no` 升序（推荐按 `order_no`，与点名顺序一致）。
- 实时性：签到成功后本地更新对应记录；同时每 5 秒轮询 `GET /rollcalls/{id}`（仅在 `calling` 状态），保证多设备同步。
- 空状态："暂无签到记录"。

#### ⑤ 缺勤记录

- 来源：`records.filter(r => r.status === "absent")`。
- 列：姓名、角色、学号、记录时间（`checked_at`，即结束时间）。
- 仅在 `ended` 后展示；`calling` 时显示占位"点名结束后生成"。
- 空状态："本次无人缺勤"。

### 3.4 历史场次页（P1）

- 列表：`GET /api/v1/rollcalls?page=1&page_size=20`，列：标题、状态、开始时间、结束时间、总人数、已签到、缺勤。
- 点击行：调用 `GET /rollcalls/{id}`，抽屉展示签到与缺勤明细。
- 空状态与分页器（`total/page/page_size` 对应第 7 章分页结构）。

## 4. 接口使用矩阵

> 所有请求经 `src/api/http.ts` 统一封装；响应统一解包 `data`，业务错误统一抛出。

| 页面/操作 | 方法 | 路径 | 关键参数 | 使用字段 |
| --- | --- | --- | --- | --- |
| 加载名单 | GET | `/api/v1/students` | `active=true` | `id, student_no, name, role, active, created_at` |
| 添加学生 | POST | `/api/v1/students` | `{name, student_no, role}` | 同上 |
| 删除学生 | DELETE | `/api/v1/students/{student_id}` | 路径参数 | `id, deleted` |
| 开始点名 | POST | `/api/v1/rollcalls` | `{title?, order_by?}` | `SessionDetail` |
| 恢复/刷新场次 | GET | `/api/v1/rollcalls/{session_id}` | 路径参数 | `SessionDetail` |
| 学生签到 | POST | `/api/v1/rollcalls/{session_id}/checkin` | `{student_id}` | `Record` |
| 结束点名 | POST | `/api/v1/rollcalls/{session_id}/end` | 无 | `SessionDetail` |
| 历史列表 | GET | `/api/v1/rollcalls` | `page, page_size, status?` | 分页 `Session[]` |

### 4.1 请求封装约定

- `baseURL = import.meta.env.VITE_API_BASE_URL || "http://localhost:8000"`。
- 成功判定：HTTP 2xx 且 `code === 0`，返回 `data`。
- 失败：构造 `ApiError { code, message, status }`，由调用方决定是否弹提示。
- 不在拦截器中无差别弹窗（避免重复提示），只在 Store 的 action 中处理。
- 超时 10 秒；网络错误统一提示"网络异常，请稍后重试"。

### 4.2 TypeScript 类型（必须与第 7 章逐字段一致）

```ts
export type Role = "学生" | "班长" | "教师";
export type SessionStatus = "calling" | "ended";
export type RecordStatus = "pending" | "present" | "absent";

export interface Student {
  id: number;
  student_no: string;
  name: string;
  role: Role;
  active: boolean;
  created_at: string;
}

export interface Session {
  id: number;
  title: string;
  status: SessionStatus;
  order_by: "student_no" | "name" | "id";
  started_at: string;
  ended_at: string | null;
  total_count: number;
  present_count: number;
  absent_count: number;
  pending_count: number;
}

export interface RecordItem {
  id: number;
  session_id: number;
  student_id: number;
  student_no: string;
  student_name: string;
  role: Role;
  order_no: number;
  status: RecordStatus;
  checked_at: string | null;
}

export interface SessionDetail {
  session: Session;
  records: RecordItem[];
}

export interface Page<T> {
  items: T[];
  total: number;
  page: number;
  page_size: number;
}
```

> 禁止使用 camelCase 自行映射；若确需转换，统一在 `api/http.ts` 的 DTO 层完成，并保持模板使用 snake_case 或统一转换后的类型，二选一且全项目一致。**建议直接使用 snake_case，零映射。**

## 5. 状态管理设计

### 5.1 student store

| state / action | 说明 |
| --- | --- |
| `students: Student[]` | 当前名单 |
| `loading: boolean` | 列表加载态 |
| `fetchStudents()` | GET `/students`，覆盖 `students` |
| `addStudent(payload)` | POST 后 `fetchStudents()`；错误向上抛出 |
| `removeStudent(id)` | DELETE 后本地移除并刷新 |

### 5.2 rollcall store

| state / action | 说明 |
| --- | --- |
| `current: SessionDetail \| null` | 当前场次 |
| `pollingTimer` | 5 秒轮询句柄 |
| `startRollcall()` | POST `/rollcalls`，写 `current`，存 `sessionStorage` |
| `restoreRollcall()` | 读 `sessionStorage` 并 GET 详情；失败清除 |
| `checkin(studentId)` | POST checkin，成功后用返回 `Record` 替换 `current.records` 对应项，并刷新统计 |
| `endRollcall()` | POST end，写 `current`，停止轮询 |
| `startPolling()` / `stopPolling()` | 仅 `calling` 时轮询，组件卸载时清理 |

### 5.3 派生数据（computed）

- `presentRecords`：`status === "present"`，按 `order_no` 升序。
- `absentRecords`：`status === "absent"`，按 `order_no` 升序。
- `pendingRecords`：`status === "pending"`。
- `currentStudent`：按轮播索引取 `records[index % records.length]`。
- `statusMap`：`student_id -> RecordStatus`，供名单表格显示状态。

## 7. 边界与异常处理

1. **重复提交**：所有写操作按钮提交期间 `loading` 禁用。
2. **轮询与操作冲突**：轮询返回的 `records` 若比本地旧（按 `status` 优先级合并：present > absent > pending），以更"新"的状态为准，避免把刚签到的状态覆盖回 pending。
3. **场次被其他设备结束**：轮询发现 `status=ended`，停止轮询、切换按钮状态并刷新缺勤记录。
4. **名单在点名中被修改**：当前场次记录不变；名单页仅提示"修改将在下次点名生效"。
5. **页面卸载**：清除轮询定时器与轮播定时器。
6. **sessionStorage 过期**：`40402` 时清除并回到未开始状态。
7. **时间显示**：`checked_at` 为 `null` 时不显示"Invalid Date"，显示"—"。

## 8. 前端验收标准

- [ ] 主流程（添加学生 → 开始 → 签到 → 结束）无刷新即可完成。
- [ ] 签到记录包含姓名、角色、学号、签到时间四项，字段与契约一致。
- [ ] 缺勤记录在结束点名后出现，且与未签到人数一致。
- [ ] 重复签到被阻止且有明确提示。
- [ ] 结束后签到被阻止且有明确提示。
- [ ] 刷新页面可恢复进行中的场次；结束后刷新仍能看到本次记录。
- [ ] 360px 宽度无横向滚动，按钮可正常点击。
- [ ] 所有接口字段名与《总体架构.md》第 7 章完全一致。
- [ ] 控制台无未捕获异常；轮询在页面卸载后停止。
