## 1. 设计目标

- 登录后按角色进入不同视图，教师、班长、学生看到的内容与操作权限不同。
- 教师/班长在一个页面完成"添加学生 → 开始点名 → 签到 → 结束点名 → 查看记录"主流程。
- 学生只看到个人签到、个人记录，不接触名单管理与点名控制。
- 简洁美观：浅色背景、单一主色、卡片式布局、清晰层级、适度动效，不堆叠装饰。
- 移动端优先适配：360px 起可用，签到按钮足够大。

## 3. 页面设计

### 3.1 页面清单

| 路由 | 页面 | 优先级 | 说明 |
| --- | --- | --- | --- |
| `/login` | 登录页 | P0 | 用户名 + 密码，成功后按角色跳转 |
| `/change-password` | 修改密码页 | P0 | 首次登录强制改密；也可从顶栏进入 |
| `/` | 角色主页 | P0 | `teacher`/`monitor` 进入课堂管理视图；`student` 进入个人签到视图 |
| `/history` | 历史场次页 | P1 | 教师/班长看全部；学生只看本人记录 |
| `/history/:id` | 场次详情页 | P1 | 可与历史页抽屉合并，二选一 |

> MVP 必须完成 `/login`、`/change-password`、`/` 三个页面；`/history` 可先做只读列表。

### 3.2 登录页与首次改密

**登录页 `/login`**

- 居中卡片：系统名「课堂签到」、用户名、密码、登录按钮；不提供注册入口。
- 前端校验非空；提交中禁用按钮；支持回车提交、密码明文切换。
- 调用 `POST /api/v1/auth/login`，成功后：
  1. 将 `access_token` 存入 `sessionStorage`（key：`tt_access_token`），关闭标签页即失效。
  2. 将 `user` 写入 auth store。
  3. `must_change_password = true` → 跳转 `/change-password`；否则按角色跳转 `/`。
- `40102`：表单下方统一提示"用户名或密码错误"，不区分账号是否存在。
- 网络错误：toast"网络异常，请稍后重试"。
- 已登录用户访问 `/login`，自动跳转 `/`。

**首次改密页 `/change-password`**

- 字段：旧密码、新密码、确认新密码。
- 新密码策略：8–64 位，至少包含 1 个字母和 1 个数字；两次输入一致。
- 调用 `POST /api/v1/auth/change-password`；成功后提示"密码已修改，请重新登录"，清除 Token 并跳转 `/login`。
- 路由守卫：`must_change_password = true` 时只允许停留本页，访问其他页面一律重定向到此页。
- 顶栏"修改密码"入口进入同一页面；非首次改密成功后同样要求重新登录。

### 3.4 教师 / 班长视图功能

#### ① 添加学生卡片（仅教师）

- 字段：`name`（必填，1–32 字符）、`student_no`（必填，6–32 字符）、`role`（下拉：学生/班长，默认"学生"）、`initial_password`（可选，6–32 字符，默认等于学号）。
- 账号自动开通：`username = student_no`，`must_change_password = true`；名单角色"学生"映射系统角色 `student`，"班长"映射 `monitor`。
- 点击"添加学生"：
  1. 前端校验非空、长度、学号格式（字母数字，允许 `-` 和 `_`，6–32 位）、初始密码长度（6–32 位）。
  2. 调用 `POST /api/v1/students`。
  3. 成功：清空姓名、学号与初始密码（保留角色）、刷新名单、提示"添加成功，学生账号已开通，首次登录需修改密码"。
  4. `40001`：学号 1–5 位或含非法字符；`40002`：初始密码不是 6–32 位；`40901`：学号已存在；`40906`：账号用户名冲突。
  5. 其他错误：`ElMessage.error(message)`。
- 提交中禁用按钮，防止重复提交；支持回车提交。
- 班长不渲染此卡片。

#### ② 点名控制卡片（教师 / 班长）

- 未开始：显示"开始点名"按钮，禁用条件为名单为空（也可点击后由后端返回 `40905`，前端双保险）。
- 点击"开始点名"：
  1. 调用 `POST /api/v1/rollcalls`，body 可传 `{ "order_by": "student_no" }`。
  2. 成功后将返回的 `SessionDetail` 写入 Store，按钮变为"点名结束"。
  3. 启动顺序轮播：按 `records` 的 `order_no` 升序，每 3 秒高亮下一位（到末尾后停在最后一位或循环，产品选择：循环轮播）。
  4. 当前学生卡片仅展示姓名、学号与"点名中"标识；教师/班长视图不提供代签按钮，签到由学生本人在自己设备完成。
- 点击"点名结束"：
  1. 弹出确认框"结束后未签到学生将记为缺勤，确认结束？"。
  2. 调用 `POST /api/v1/rollcalls/{id}/end`。
  3. 成功：停止轮播，按钮置灰为"已结束"，刷新签到/缺勤记录与统计，`ElMessage.success("点名已结束")`。
  4. 若返回 `40903`：提示并同步场次状态。
- 页面刷新恢复：将 `session_id` 存入 `sessionStorage`；刷新后调用 `GET /rollcalls/{id}`，若 `status=calling` 则恢复轮播与按钮状态；若 `40402` 则清除本地缓存。

#### ③ 学生名单（教师可管理，班长只读）

- 数据来源：`GET /api/v1/students`（默认 `active=true`）。
- 展示：姓名、学号、角色、本次状态（未点名时显示"—"；点名中按 `records` 映射为"已签到/待签到/缺勤"）、操作（删除，仅教师可见）。
- 删除：二次确认后调用 `DELETE /students/{id}`（软删除并禁用账号），成功后刷新名单。点名进行中删除学生仅影响下一次场次，不改变当前场次记录。
- 名单为空时显示空状态："还没有学生，请先添加"。

#### ④ 签到记录

- 来源：当前 `SessionDetail.records.filter(r => r.status === "present")`。
- 列：姓名、角色、学号、签到时间（本地时区格式化）。
- 默认按 `checked_at` 升序或 `order_no` 升序（推荐按 `order_no`，与点名顺序一致）。
- 实时性：签到成功后本地更新对应记录；同时每 5 秒轮询 `GET /rollcalls/{id}`（仅在 `calling` 状态），保证多设备同步。
- 空状态："暂无签到记录"。

#### ⑤ 缺勤记录

- 来源：`records.filter(r => r.status === "absent")`。
- 列：姓名、角色、学号、记录时间（`checked_at`，即结束时间）。
- 仅在 `ended` 后展示；`calling` 时显示占位"点名结束后生成"。
- 空状态："本次无人缺勤"。

#### ⑥ 我的签到卡片（仅班长）

- 复用 `StudentCheckinCard`（monitor 模式），仅在 `user.role === "monitor"` 且存在进行中场次时渲染。
- 展示本人姓名、学号与状态（待签到/已签到/缺勤）；点击"签到"调用 `POST /rollcalls/{id}/checkin`，无请求体。
- 成功后按钮变绿色"已签到"并禁用；`40902` 置为已签到，`40903` 提示点名已结束并刷新，`40301` 提示账号未绑定学生。
- 教师不渲染此卡片；学生主页使用同一组件的 student 模式。

### 3.5 学生视图功能

- 当前点名卡片：
  - 页面加载时调用 `GET /api/v1/rollcalls?status=calling&page_size=1`，取最新进行中场次；再调用 `GET /rollcalls/{id}`（后端只返回本人的记录与本人维度统计）。
  - 显示本人姓名、学号、当前状态（待签到/已签到/缺勤）与"签到"按钮。
  - 点击签到：调用 `POST /rollcalls/{id}/checkin`，无请求体；成功按钮变绿色"已签到"并禁用。
  - 无进行中场次：显示"当前没有进行中的点名"；列出最近一次已结束场次的本人结果。
  - `40902`：按钮置为"已签到"；`40903`：提示"点名已结束"并刷新；`40904`：提示"你不在本次点名名单中"；`40402`：场次不存在或无权查看，回到空状态。
- 我的签到记录：当前场次本人 `status=present` 的记录，展示场次标题、签到时间。
- 我的缺勤记录：当前/最近场次本人 `status=absent` 的记录，展示场次标题、记录时间。
- 历史入口：进入 `/history`，只能看到本人参与过的场次与本人记录（后端按登录身份过滤，前端直接展示）。
- 轮询：点名进行中每 5 秒刷新当前场次；页面卸载时清理定时器。
- 不显示名单管理、点名控制与全班统计；接口返回的统计字段也仅为本人维度（`total_count=1`，其余 0/1）。

### 3.6 历史场次页（P1）

- 教师/班长：`GET /api/v1/rollcalls?page=1&page_size=20`，列：标题、状态、开始时间、结束时间、总人数、已签到、缺勤。
- 学生：同一接口，后端只返回本人参与过的场次，统计为本人维度；列表列改为：标题、状态、开始时间、结束时间、本人维度统计（总人数=1、已签到/缺勤 0/1）。列表**不显示"我的时间"**。
- 点击行：调用 `GET /rollcalls/{id}`，抽屉展示记录；学生只看到本人记录与本人统计，未参与场次返回 `40402`；本人签到时间从详情 `Record.checked_at` 查看。
- 空状态与分页器（`total/page/page_size` 对应第 7 章分页结构）。

### 3.7 多班级界面约定（v1.3）

- **教师**：顶栏显示班级选择器与"班级管理"入口；切换班级后刷新名单、当前场次与历史。
- **班级管理弹窗**：班级列表、新建（`name`、`code`）、停用；停用仍有在册学生的班级时提示 `40908`。
- **班长/学生**：只显示本人班级名称，不渲染班级切换器与管理入口；请求由后端强制本班。
- **添加学生**：表单新增班级选择（默认当前班级）；`POST /students` 必须带 `class_id`。
- **点名/历史**：`POST /rollcalls` 必须带 `class_id`，`GET /rollcalls` 可带 `class_id`；班长/学生不传，由后端强制本班。
- **学生视图**：只显示本班当前场次与本人记录；跨班数据不渲染。
- **错误处理**：`40301` 提示无权访问该班；`40402` 场次不存在或无权；`40908` 提示先转出/删除学生。

## 4. 接口使用矩阵

> 所有请求经 `src/api/http.ts` 统一封装；响应统一解包 `data`，业务错误统一抛出。

| 页面/操作 | 方法 | 路径 | 关键参数 | 使用字段 | 允许角色 |
| --- | --- | --- | --- | --- | --- |
| 登录 | POST | `/api/v1/auth/login` | `{username, password}` | `LoginResponse` | 公开 |
| 恢复登录态 | GET | `/api/v1/auth/me` | 无（Token） | `User` | 全部已登录 |
| 修改密码 | POST | `/api/v1/auth/change-password` | `{old_password, new_password}` | `{changed}` | 全部已登录 |
| 加载名单 | GET | `/api/v1/students` | `class_id?, active=true` | `id, class_id, student_no, name, role, active, created_at` | 教师、班长 |
| 添加学生 | POST | `/api/v1/students` | `{class_id, name, student_no, role, initial_password?, create_account?}` | `Student` | 教师 |
| 删除学生 | DELETE | `/api/v1/students/{student_id}` | 路径参数 | `id, deleted` | 教师 |
| 班级列表 | GET | `/api/v1/classes` | `active?` | `Class[]` | 全部已登录（班长/学生仅本班） |
| 创建班级 | POST | `/api/v1/classes` | `{name, code}` | `Class` | 教师 |
| 停用班级 | DELETE | `/api/v1/classes/{class_id}` | 路径参数 | `{id, deleted}` | 教师 |
| 开始点名 | POST | `/api/v1/rollcalls` | `{class_id, title?, order_by?}` | `SessionDetail` | 教师、班长 |
| 恢复/刷新场次 | GET | `/api/v1/rollcalls/{session_id}` | 路径参数 | `SessionDetail`（学生仅本人记录与统计；跨班 40402） | 全部已登录 |
| 本人签到 | POST | `/api/v1/rollcalls/{session_id}/checkin` | 无请求体（身份取自 Token） | `Record` | 学生、班长 |
| 结束点名 | POST | `/api/v1/rollcalls/{session_id}/end` | 无 | `SessionDetail` | 教师、班长 |
| 当前场次（学生/班长） | GET | `/api/v1/rollcalls` | `status=calling, page_size=1` | 分页 `Session[]`（服务端强制本班） | 全部已登录 |
| 历史列表 | GET | `/api/v1/rollcalls` | `class_id?, page, page_size, status?` | 分页 `Session[]`（学生仅本人参与） | 全部已登录 |

### 4.1 请求封装约定

- `baseURL = import.meta.env.VITE_API_BASE_URL || "http://localhost:8000"`。
- 请求拦截器从 `sessionStorage.tt_access_token` 读取 Token，存在则添加 `Authorization: Bearer <token>`；登录接口除外。
- 成功判定：HTTP 2xx 且 `code === 0`，返回 `data`。
- 失败：构造 `ApiError { code, message, status }`，由调用方决定是否弹提示。
- 统一处理：
  - `40101` / `40103`：清除 Token 与 auth store，跳转 `/login`（登录请求自身除外）。
  - `40302`：跳转 `/change-password`。
  - `40301`：提示"无权执行该操作"，不跳转。
- 不在拦截器中无差别弹窗（避免重复提示），只在 Store 的 action 中处理。
- 超时 10 秒；网络错误统一提示"网络异常，请稍后重试"。

## 5. 状态管理设计

### 5.1 auth store

| state / action | 说明 |
| --- | --- |
| `token: string \| null` | 从 `sessionStorage.tt_access_token` 初始化 |
| `user: User \| null` | 当前登录用户 |
| `initialized: boolean` | 是否已完成启动时的登录态恢复 |
| `login(username, password)` | POST `/auth/login`，保存 Token 与用户 |
| `fetchMe()` | GET `/auth/me`，刷新用户信息；401 时清除 |
| `changePassword(oldPwd, newPwd)` | POST `/auth/change-password`，成功后清除登录态 |
| `logout()` | 清除 Token、`sessionStorage` 与 store，跳转 `/login` |
| `isTeacher` / `isMonitor` / `isStudent` | 由 `user.role` 派生 |
| `canManageStudents` | 仅 `role === "teacher"` |
| `mustChangePassword` | `user.must_change_password` |

- 路由守卫在首次进入时若 `initialized=false` 且有 Token，先 `fetchMe()`；失败则跳转登录页。
- 角色不匹配的页面直接重定向 `/`，并提示"无权访问"。

### 5.2 student store

| state / action | 说明 |
| --- | --- |
| `students: Student[]` | 当前名单 |
| `loading: boolean` | 列表加载态 |
| `fetchStudents()` | GET `/students`，覆盖 `students` |
| `addStudent(payload)` | POST 后 `fetchStudents()`；错误向上抛出 |
| `removeStudent(id)` | DELETE 后本地移除并刷新 |

### 5.3 rollcall store

| state / action | 说明 |
| --- | --- |
| `current: SessionDetail \| null` | 当前场次 |
| `pollingTimer` | 5 秒轮询句柄 |
| `startRollcall()` | 教师/班长：POST `/rollcalls`，写 `current`，存 `sessionStorage` |
| `restoreRollcall()` | 教师/班长：读 `sessionStorage` 并 GET 详情；失败清除 |
| `fetchCurrentSession()` | 学生：GET `/rollcalls?status=calling&page_size=1`（后端只返回本人参与的场次），有则再取详情 |
| `fetchSession(sessionId)` | 通用：GET `/rollcalls/{id}` |
| `checkin()` | 学生/班长：POST checkin（无请求体），成功后用返回 `Record` 替换 `current.records` 对应项并刷新统计 |
| `endRollcall()` | 教师/班长：POST end，写 `current`，停止轮询 |
| `startPolling()` / `stopPolling()` | 仅 `calling` 时轮询，组件卸载时清理 |

### 5.4 派生数据（computed）

- `presentRecords`：`status === "present"`，按 `order_no` 升序。
- `absentRecords`：`status === "absent"`，按 `order_no` 升序。
- `pendingRecords`：`status === "pending"`。
- `currentStudent`：按轮播索引取 `records[index % records.length]`。
- `myRecord`：学生视图中 `records.find(r => r.student_id === user.student_id)`。
- `statusMap`：`student_id -> RecordStatus`，供名单表格显示状态。

## 7. 边界与异常处理

1. **重复提交**：所有写操作按钮提交期间 `loading` 禁用。
2. **未登录/Token 过期**：路由守卫拦截，跳转 `/login`，不渲染受保护内容。
3. **首次改密未完成**：守卫强制跳转 `/change-password`；后端返回 `40302` 时同样处理。
4. **角色越权**：不渲染无权限组件；即使手动输入 URL，守卫与后端 `40301` 双重拦截。
5. **轮询与操作冲突**：轮询返回的 `records` 若比本地旧（按 `status` 优先级合并：present > absent > pending），以更"新"的状态为准，避免把刚签到的状态覆盖回 pending。
6. **场次被其他设备结束**：轮询发现 `status=ended`，停止轮询、切换按钮状态并刷新缺勤记录。
7. **名单在点名中被修改**：当前场次记录不变；名单页仅提示"修改将在下次点名生效"。
8. **页面卸载**：清除轮询定时器与轮播定时器。
9. **sessionStorage 过期**：`40402` 时清除并回到未开始状态。
10. **学生无当前场次**：显示空状态，不显示签到按钮。
11. **时间显示**：`checked_at` 为 `null` 时不显示"Invalid Date"，显示"—"。
