## 1. 职责与边界

后端是**唯一业务规则实现方**，职责包括：

1. 接收并校验前端请求（Pydantic）。
2. 认证与鉴权：签发/校验 JWT，按 `user.role` 限制接口访问。
3. 实现点名场次状态流转、签到幂等、缺勤生成。
4. 通过 Repository 与数据库交互，管理事务。
5. 统一响应封装、错误码、日志。
6. 自动生成 OpenAPI，供前端生成类型与联调。

**不负责**：页面渲染、前端状态。

## 4. 接口详细设计

### 4.0 统一响应与异常

所有接口返回：

```json
{ "code": 0, "message": "success", "data": {} }
```

失败：

```json
{ "code": 40901, "message": "该学号已存在", "data": null }
```

- 业务异常统一抛 `ApiError(code, message, http_status)`，由全局异常处理器转换为上述结构。
- Pydantic 校验失败映射为 `40001`，`message` 取第一条可读错误，`data` 中可附带 `fields`（可选，前端不强制使用）。
- 未捕获异常：记录 `request_id` 与堆栈，返回 `50000`，不暴露内部细节。

**中间件**：为每个请求生成 `request_id`（UUID），写入响应头 `X-Request-ID` 与日志。

**认证与鉴权**

- 除 `GET /health`、`POST /auth/login` 外，所有接口要求 `Authorization: Bearer <access_token>`。
- 依赖链：`get_current_user`（解析 JWT、校验用户 `active`）→ `require_password_changed`（拦截 `must_change_password=true`）→ `require_roles(...)`（角色白名单）。
- Token 缺失/无效 → `40101`；过期 → `40103`；角色不足 → `40301`；未改初始密码 → `40302`。
- Token claims：`sub`（user.id）、`username`、`role`、`student_id`、`iat`、`exp`、`jti`。
- 认证接口本身（`/auth/me`、`/auth/change-password`）不经过 `require_password_changed`，否则无法完成改密。

### 4.2 GET `/api/v1/students`

- 用途：获取学生名单。
- 权限：`teacher`、`monitor`；`student` 返回 `40301`。
- Query：

| 参数 | 类型 | 必填 | 默认 | 校验 |
| --- | --- | --- | --- | --- |
| `keyword` | string | 否 | — | 长度 ≤ 32，匹配姓名或学号模糊查询 |
| `active` | boolean | 否 | `true` | 是否只返回在册学生 |

- 成功 200：

```json
{
  "code": 0,
  "message": "success",
  "data": [
    {
      "id": 1,
      "student_no": "20230001",
      "name": "张三",
      "role": "学生",
      "active": true,
      "created_at": "2026-11-05T10:00:00+08:00"
    }
  ]
}
```

- 排序：`student_no ASC, id ASC`。
- 错误：`40001`（keyword 超长）。

**说明**：名单接口不分页，MVP 单课堂人数 ≤ 200，直接返回全量；若后续超过 500 人再增加分页（需走契约变更）。

### 4.3 POST `/api/v1/students`

- 用途：添加学生，并在同一事务中自动开通登录账号。
- 权限：仅 `teacher`；`monitor`/`student` 返回 `40301`。
- 请求体：

```json
{
  "student_no": "20230001",
  "name": "张三",
  "role": "学生",
  "initial_password": "20230001",
  "create_account": true
}
```

| 字段 | 类型 | 必填 | 校验 |
| --- | --- | --- | --- |
| `student_no` | string | 是 | 6–32 字符，正则 `^[A-Za-z0-9_-]+$`，去除首尾空格 |
| `name` | string | 是 | 1–32 字符，去除首尾空格，不允许纯空白 |
| `role` | string | 否 | 枚举 `学生`/`班长`，默认 `学生`（MVP 添加表单不提供"教师"） |
| `initial_password` | string | 否 | `create_account=true` 时可选，6–32 字符；默认等于 `student_no` |
| `create_account` | boolean | 否 | 默认 `true`；`false` 时仅添加名单，不创建账号 |

- 成功 201：返回 `Student` 完整对象（不返回密码）。
- 错误：
  - `40001`：字段缺失、超长、学号少于 6 位或格式非法、role 为"教师"。
  - `40002`：初始密码不是 6–32 字符。
  - `40901`：`student_no` 已存在（包含已软删除学生，学号全局唯一不可复用）。
  - `40906`：账号用户名冲突（通常与学号冲突同时出现）。

**实现要点**

1. 先 `strip()`，再校验。
2. 依赖数据库唯一约束兜底，捕获 `IntegrityError` 并转为 `40901` / `40906`，避免并发重复。
3. 不信任前端传入的 `id`、`active`、`created_at`。
4. 账号：`username = student_no`，`role` 映射 `学生 → student`、`班长 → monitor`，`student_id` 指向新学生，`must_change_password = true`，密码使用 bcrypt 哈希。
5. 学生与账号在同一事务内创建；账号失败整体回滚，避免"有名单无账号"。
6. 响应不含 `initial_password`；前端提示"初始密码为教师填写值或学号，首次登录需修改"。

### 4.4 DELETE `/api/v1/students/{student_id}`

- 用途：从名单移除学生（软删除，保留历史记录），同时禁用其登录账号。
- 权限：仅 `teacher`；`monitor`/`student` 返回 `40301`。
- 路径参数：`student_id` 正整数。
- 成功 200：

```json
{ "code": 0, "message": "success", "data": { "id": 1, "deleted": true } }
```

- 错误：
  - `40401`：学生不存在或已删除。
- 实现：`UPDATE students SET active = false WHERE id = :id AND active = true`；`rowcount=0` 返回 `40401`；同一事务执行 `UPDATE users SET active = false WHERE student_id = :id`。
- 不影响已创建场次的 `attendance_records`（记录存快照）；账号禁用后无法再登录，但历史签到记录保留。

> 不提供修改学生接口（MVP）。若后续新增，必须更新契约与前端类型。

### 4.5 POST `/api/v1/rollcalls`

- 用途：开始点名，创建场次并为当前在册学生生成 `pending` 记录。
- 权限：`teacher`、`monitor`；`student` 返回 `40301`。
- 请求体：

```json
{ "title": "2026-11-05 课堂点名", "order_by": "student_no" }
```

| 字段 | 类型 | 必填 | 默认 | 校验 |
| --- | --- | --- | --- | --- |
| `title` | string | 否 | 服务端生成 `YYYY-MM-DD 课堂点名` | 1–64 字符 |
| `order_by` | string | 否 | `student_no` | 枚举 `student_no` / `name` / `id` |

- 成功 201：返回 `SessionDetail`。
- 错误：
  - `40001`：`order_by` 非法、title 超长。
  - `40905`：当前 `active = true` 的学生数为 0。

**事务步骤（必须在同一事务）**

1. 查询 `students WHERE active = true`，按 `order_by` 排序；为 0 则抛 `40905`。
2. 插入 `rollcall_sessions`：`status='calling'`、`started_at=now()`、`order_by`、`title`。
3. 按排序结果批量插入 `attendance_records`：`order_no` 从 1 递增，`status='pending'`，写入 `student_no/student_name/role` 快照，`checked_at=NULL`。
4. 提交后重新查询场次与记录，聚合统计后返回。

**排序实现**

| order_by | SQL 排序 |
| --- | --- |
| `student_no` | `student_no ASC, id ASC` |
| `name` | `name ASC, id ASC`（中文按数据库排序规则；SQLite 为二进制序，可接受） |
| `id` | `id ASC` |

- 成功响应示例：

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "session": {
      "id": 10,
      "title": "2026-11-05 课堂点名",
      "status": "calling",
      "order_by": "student_no",
      "started_at": "2026-11-05T10:00:00+08:00",
      "ended_at": null,
      "total_count": 3,
      "present_count": 0,
      "absent_count": 0,
      "pending_count": 3
    },
    "records": [
      {
        "id": 100,
        "session_id": 10,
        "student_id": 1,
        "student_no": "20230001",
        "student_name": "张三",
        "role": "学生",
        "order_no": 1,
        "status": "pending",
        "checked_at": null
      }
    ]
  }
}
```

### 4.6 GET `/api/v1/rollcalls`

- 用途：历史/当前场次分页列表。
- 权限：全部已登录角色。教师/班长返回全部场次；学生只返回其参与过（`attendance_records` 中存在本人记录）的场次；学生列表的统计字段为本人维度（`total_count=1`，其余 0/1）。
- 学生列表**不返回** `my_status` / `my_checked_at`：本人状态由 `present_count` / `absent_count` 推断，签到时间进入详情读取 `Record.checked_at`。
- Query：

| 参数 | 类型 | 必填 | 默认 | 校验 |
| --- | --- | --- | --- | --- |
| `page` | integer | 否 | 1 | ≥ 1 |
| `page_size` | integer | 否 | 20 | 1–100 |
| `status` | string | 否 | — | `calling` / `ended` |

- 成功 200：

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "items": [ { "…Session…": "含 total_count/present_count/absent_count/pending_count" } ],
    "total": 42,
    "page": 1,
    "page_size": 20
  }
}
```

- 排序：`started_at DESC, id DESC`。
- 统计字段通过子查询/聚合实时计算，确保准确。
- 错误：`40001`（分页参数越界、status 非法）。

### 4.7 GET `/api/v1/rollcalls/{session_id}`

- 用途：场次详情，供页面刷新恢复、轮询、历史明细。
- 权限：全部已登录角色。
  - `teacher` / `monitor`：返回全班统计与全部 `records`。
  - `student`：只返回本人记录与本人维度统计；若不在该场次，返回 `40402`（不区分"不存在"与"无权"，防止枚举）。
- 成功 200：`SessionDetail`，`records` 按 `order_no ASC` 排序。
- 错误：`40402` 场次不存在，或学生未参与该场次。
- 性能：单场次 ≤ 200 条记录，一次查询 + 内存聚合即可；不使用 N+1。

### 4.8 POST `/api/v1/rollcalls/{session_id}/checkin`

- 用途：当前登录学生本人签到；班长通过"我的签到"卡片调用同一接口。
- 权限：`student`、`monitor`；`teacher` 或 `student_id` 为空的账号返回 `40301`。
- 请求体：**无**。签到学生身份取自 JWT 中的 `student_id`，不接受前端传入。
- 成功 200：返回更新后的 `Record`：

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "id": 100,
    "session_id": 10,
    "student_id": 1,
    "student_no": "20230001",
    "student_name": "张三",
    "role": "学生",
    "order_no": 1,
    "status": "present",
    "checked_at": "2026-11-05T10:01:20+08:00"
  }
}
```

- 错误：

| 场景 | code | HTTP |
| --- | --- | --- |
| 未改初始密码 | 40302 | 403 |
| 教师账号或无绑定学生 | 40301 | 403 |
| 场次不存在 | 40402 | 404 |
| 场次已结束 | 40903 | 409 |
| 学生不在该场次 | 40904 | 409 |
| 已签到 | 40902 | 409 |

**并发安全实现（推荐原子更新）**

```sql
UPDATE attendance_records
SET status = 'present', checked_at = :now
WHERE session_id = :session_id
  AND student_id = :current_user_student_id
  AND status = 'pending';
```

- `student_id` 必须来自 `current_user.student_id`，禁止从请求体读取。
- `rowcount = 1`：成功，查询并返回记录。
- `rowcount = 0`：按顺序诊断——场次不存在 → 40402；场次 `ended` → 40903；记录不存在 → 40904；记录已 `present` → 40902。
- 时间由服务端生成（UTC），不得使用前端时间。

### 4.9 POST `/api/v1/rollcalls/{session_id}/end`

- 用途：结束点名，未签到学生转缺勤。
- 权限：`teacher`、`monitor`；`student` 返回 `40301`。
- 请求体：无（如需备注可后续扩展，禁止现在加字段）。
- 成功 200：返回结束后的 `SessionDetail`（含签到与缺勤记录）。
- 错误：
  - `40402` 场次不存在。
  - `40903` 场次已结束（不可重复结束）。

**事务步骤（必须同一事务）**

```text
BEGIN
1. SELECT ... FROM rollcall_sessions WHERE id = :id FOR UPDATE   -- 不存在 → 40402
2. 若 status = 'ended' → 40903
3. UPDATE attendance_records
   SET status = 'absent', checked_at = :ended_at
   WHERE session_id = :id AND status = 'pending'
4. UPDATE rollcall_sessions
   SET status = 'ended', ended_at = :ended_at
   WHERE id = :id AND status = 'calling'
5. 重新聚合统计并读取 records
COMMIT
```

- `ended_at` 由服务端生成一次，签到与缺勤时间口径一致。
- SQLite 不支持 `FOR UPDATE`，由 SQLAlchemy 方言自动忽略；生产 PostgreSQL 生效。也可用条件更新 `WHERE status='calling'` 的 `rowcount` 防并发重复结束。

### 4.10 认证接口

#### 4.10.1 POST `/api/v1/auth/login`

- 用途：用户名 + 密码登录，签发 JWT。
- 权限：公开（无需 Token）。
- 请求体：

```json
{ "username": "20230001", "password": "20230001" }
```

| 字段 | 类型 | 必填 | 校验 |
| --- | --- | --- | --- |
| `username` | string | 是 | `strip` 后 1–32 字符 |
| `password` | string | 是 | 1–64 字符；登录只校验匹配，不套用新密码策略 |

- 流程：
  1. 按 `username` 查询 `users`，要求 `active = true`。
  2. 使用 bcrypt 校验密码。
  3. 用户不存在、密码错误、账号禁用统一返回 `40102`，不暴露账号是否存在。
  4. 更新 `last_login_at`。
  5. 签发 JWT（HS256，`exp = now + 480min`）。
- 成功 200：

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "access_token": "eyJhbGciOiJIUzI1NiIs...",
    "token_type": "bearer",
    "expires_in": 28800,
    "user": {
      "id": 1,
      "username": "20230001",
      "role": "student",
      "display_name": "张三",
      "student_id": 1,
      "must_change_password": true,
      "active": true,
      "created_at": "2026-11-05T10:00:00+08:00",
      "last_login_at": "2026-11-05T10:00:00+08:00"
    }
  }
}
```

- 错误：`40001` 参数缺失/超长；`40102` 用户名或密码错误。
- 登录成功但 `must_change_password=true` 时仍返回 Token，前端据 `user.must_change_password` 跳转改密页；后端业务接口由 `40302` 兜底。
- 可选加固（P1）：同一用户名连续失败 5 次锁定 5 分钟（内存计数），失败日志不记录密码。

#### 4.10.2 GET `/api/v1/auth/me`

- 用途：获取当前登录用户，供前端刷新恢复登录态。
- 权限：全部已登录角色（允许 `must_change_password=true`）。
- 成功 200：`User` 对象。
- 错误：`40101` Token 缺失/无效；`40103` Token 过期。

#### 4.10.3 POST `/api/v1/auth/change-password`

- 用途：修改本人密码；首次登录强制改密也走此接口。
- 权限：全部已登录角色；**不经过** `require_password_changed`。
- 请求体：

```json
{ "old_password": "20230001", "new_password": "Abc12345" }
```

| 字段 | 类型 | 必填 | 校验 |
| --- | --- | --- | --- |
| `old_password` | string | 是 | 1–64 字符 |
| `new_password` | string | 是 | 8–64 字符，至少 1 个字母 + 1 个数字，且不能与旧密码相同 |

- 流程：
  1. 校验旧密码，错误返回 `40003`。
  2. 校验新密码策略，失败返回 `40004`。
  3. bcrypt 更新 `password_hash`，置 `must_change_password = false`，更新 `updated_at`。
- 成功 200：

```json
{ "code": 0, "message": "success", "data": { "changed": true } }
```

- 错误：`40004` 新密码不符合策略；`40003` 旧密码不正确；`40101`/`40103` 登录态问题。
- JWT 为无状态，修改密码不会使旧 Token 立即失效；前端在改密成功后清除 Token 并要求重新登录。生产增强（P1）：`users.token_version` 递增并在校验时比对。

#### 4.10.4 教师种子账号

- 脚本：`backend/scripts/seed_teacher.py`。
- 读取 `SEED_TEACHER_USERNAME`（默认 `teacher`）与 `SEED_TEACHER_PASSWORD`；未设置密码时随机生成 12 位并仅打印一次。
- 创建 `role = teacher`、`student_id = NULL`、`must_change_password = true` 的账号；用户名已存在时默认跳过，`--reset` 可重置密码。
- 严禁把明文密码写入迁移文件或提交到仓库。

### 5.4 统计聚合

```sql
SELECT status, COUNT(*) AS cnt
FROM attendance_records
WHERE session_id = :session_id
GROUP BY status;
```

- `total_count = pending + present + absent`
- 场次列表使用窗口/子查询一次性聚合，避免每条场次单独查询（N+1）。

## 6. 数据校验规则

| 字段 | 规则 | 失败 code |
| --- | --- | --- |
| `name` | `strip` 后 1–32 字符，非纯空白 | 40001 |
| `student_no` | `strip` 后 6–32，`^[A-Za-z0-9_-]+$` | 40001 |
| `role`（名单） | 枚举：`学生`、`班长`（MVP 添加表单不提供"教师"） | 40001 |
| `initial_password` | 6–32 字符；默认等于 `student_no` | 40002 |
| `create_account` | 布尔，默认 `true` | 40001 |
| `username` | `strip` 后 1–32 字符 | 40001 |
| `password`（登录） | 1–64 字符 | 40001 |
| `old_password` | 1–64 字符 | 40001 |
| `new_password` | 8–64，至少 1 字母 + 1 数字，且不等于旧密码 | 40004 |
| `title` | `strip` 后 1–64 字符 | 40001 |
| `order_by` | 枚举：`student_no`、`name`、`id` | 40001 |
| `page` | ≥ 1 | 40001 |
| `page_size` | 1–100 | 40001 |
| `status`（查询） | `calling`、`ended` | 40001 |
| `session_id` | 正整数 | 40001 |
| 签到请求体 | 必须为空；多余字段忽略，服务端不接受 `student_id` | — |

- 所有字符串输出前不做 HTML 转义（JSON），由前端渲染时转义；后端不返回富文本。
- 日志中姓名与学号可记录，但不记录请求体全文（避免批量个人信息泄露）。

## 7. 事务与并发

| 场景 | 隔离要求 | 措施 |
| --- | --- | --- |
| 登录 | 一致性 | 读取用户 + 更新 last_login_at；失败统一 40102 |
| 添加学生 | 唯一约束 | 学生 + 账号同一事务；捕获 `IntegrityError` → 40901/40906 |
| 删除学生 | 一致性 | 软删除学生 + 禁用账号同一事务 |
| 修改密码 | 一致性 | 校验旧密码后更新哈希与 must_change_password |
| 开始点名 | 一致性 | 单事务插入场次 + 记录；失败整体回滚 |
| 签到 | 防重复 | 条件更新 `WHERE status='pending'`，依据 `rowcount` |
| 结束点名 | 防重复结束 | 条件更新 `WHERE status='calling'` + 事务 |
| 并发签到与结束 | 不丢数据 | 结束只更新 `pending`；签到只更新 `pending`；二者必有一方生效 |

- 默认隔离级别：PostgreSQL `READ COMMITTED`；SQLite 使用默认串行写。
- 不在应用层做"先查后改"的唯一性判断作为最终依据，数据库约束与条件更新才是权威。
- 登录失败与账号不存在不做区分；密码比对使用 bcrypt，禁止明文比较。

## 8. 日志与可观测性

- 每条请求日志字段：`request_id`、`method`、`path`、`status_code`、`duration_ms`、`error_code`、`user_id`（已登录时）。

### 10.2 必测用例

**认证与权限**

1. 正确用户名/密码登录 → 200；`token_type=bearer`、`expires_in=28800`、`user` 字段完整。
2. 错误密码、不存在用户、禁用账号 → 均返回 401 / 40102，提示一致。
3. 无 Token 访问受保护接口 → 40101；伪造 Token → 40101；过期 Token → 40103。
4. 学生访问 `GET /students`、`POST /rollcalls`、`POST /end` → 40301；教师调用签到 → 40301；班长调用签到 → 200，记录角色为"班长"。
5. 教师种子账号首次登录 `must_change_password=true`，访问业务接口 → 40302；改密后恢复。
6. 改密：旧密码错误 → 40003；新密码过弱 → 40004；成功后旧密码不能登录、新密码可登录。
7. 添加学生自动创建账号：`username=student_no`、角色映射正确、`must_change_password=true`；初始密码可登录。
8. 删除学生后账号 `active=false`，登录返回 40102；历史记录仍可查询。
9. 学生 `GET /rollcalls/{id}` 只返回本人记录与本人维度统计；访问未参与场次 → 40402。
10. 学生签到身份取自 Token；请求体传入其他 `student_id` 不生效。

**学生**

11. 添加学生成功 → 201，字段完整，`role` 默认"学生"。
12. 重复学号 → 409 / 40901；账号用户名冲突 → 40906。
13. 空姓名、超长姓名、1–5 位学号、非法学号 → 400 / 40001。
14. 列表按学号升序；`keyword` 模糊匹配；`active=false` 过滤正确；SQLite 下模糊查询正常（SQLAlchemy `ilike` 按方言降级）。
15. 删除学生 → `active=false`；再次删除 → 40401；已删除学生不出现在默认列表。

**点名**

16. 空名单开始点名 → 409 / 40905，且不创建场次。
17. 开始点名 → 201；`total_count = pending_count = 在册人数`；`order_no` 连续从 1 开始。
18. 签到成功 → `present`，`checked_at` 非空；统计 `present_count +1`、`pending_count -1`。
19. 重复签到 → 409 / 40902，记录仍只有一条。
20. 非本场学生签到 → 409 / 40904。
21. 结束点名 → 所有 `pending` 变 `absent`；`present + absent = total`；`ended_at` 非空。
22. 结束后签到 → 409 / 40903。
23. 重复结束 → 409 / 40903。
24. 场次不存在 → 404 / 40402。
25. 历史分页：`total/page/page_size` 正确，按开始时间倒序。

**并发**

26. 同一学生并发签到两次，仅一次成功，记录唯一。
27. 并发签到与结束，最终状态一致，无 `pending` 残留。
